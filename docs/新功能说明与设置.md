## 1. 一句话介绍 + 安装

**一句话**：OptimisedCraftingSystem 是一个「合成全流程合理化」模组 —— 它在**合成之前**就算清楚「这次会用掉哪一件材料、消耗多少、产物会落到哪里」，并把结果显示在原版 C 键合成界面里，玩家可以随时手动改派材料与存放目标（`Plugin.cs:12-16`、`CraftSession.cs:6-16`）。

**安装**：

1. 把 `OptimisedCraftingSystem.dll` 放进 `<游戏目录>\BepInEx\plugins\`。
2. **必须删除旧的 `CraftingLogic.dll`**（旧模组 BetterInventoryLogic，GUID `com.balaur.BetterLogic`）。
   原因在 `Plugin.cs:68-82`：插件启动时会检测 `Chainloader.PluginInfos` 里是否还有 `com.balaur.BetterLogic`，如果有就打印**红色错误**（原文见 `Plugin.cs:74-75`）：
   > 检测到旧模组 BetterInventoryLogic（com.balaur.BetterLogic）仍在运行！它与本模组补丁重叠、设置项同名，请删除 BepInEx/plugins/CraftingLogic.dll 后重启游戏，否则行为不可预测。
   两者不能共存的三个具体理由（`Plugin.cs:12-16`）：补**同一批方法**（`Recipe.GetItemsForRecipe` / `RecipeResult.SpawnResult` / `Settings.DefaultSettings` / `Locale.LoadLanguage`），同时存在时补丁互相覆盖；设置项**重名**；两者都会改液体存放行为。
3. 启动游戏后 `BepInEx\LogOutput.log` 里应出现（`Plugin.cs:45`）：
   `OptimisedCraftingSystem 1.0.0 已加载（Harmony 补丁已应用）。`
   如果看到上一条错误，说明第 2 步没做。
4. 无需任何配置文件：**本模组不使用 BepInEx 的 `.cfg`**，所有设置都注册进游戏自己的设置菜单，并保存在游戏的 `settings.json` 里（`ModSettings.cs:9-18`、`Patches\PatchSettings.cs:9-12`）。
5. **进关卡后会自动打一份自检报告**（`Core\SelfCheck.cs`，由 `Plugin.cs:52` 每帧驱动）：主菜单里配方表还是空的，会先提示一句「`[自检] 配方表还是空的（多半还在主菜单），进关卡后会自动再查一次。`」（`SelfCheck.cs:40-45`），进关卡后自动输出
   - `[自检] 语言=… 设置项=… 项 热键=… 字体=…`（`SelfCheck.cs:50-54`，设置项数量应为 **36**＝35 个开关 + 1 个按键项；10-17 07:00:28 版之前是 32＝31+1，字体若是「无（中文可能显示为方框）」见 §6）
- 07:28:16 版又加了三个 `ocs.craft.*` 项（容器内容物转移 / 优先消耗空瓶 / 瓶子被消耗时救出液体），报告里还会多一条 `[自检] RecipeItem.UseItem ← 本模组：…`（`SelfCheck.cs:83-88`），所以设置项一栏应看到 **36 项＝35 个开关 + 1 个按键项**。
   - `[自检] 配方=… 个 物品类型=… 种 玩家=在场`（`SelfCheck.cs:56-65`）
   - 逐条补丁归属：`[自检] Recipe.TryMake ← 本模组：…；其它模组：…`（`SelfCheck.cs:67-88`、`:89-112`）
   若看到 `← 关键补丁未生效！`（`SelfCheck.cs:105`），说明补丁没挂上，功能不会生效。

## 2. 新功能逐项说明

### 2.1 智能选材（按真实成本挑材料）

| | |
|---|---|
| **作用** | 合成时不再按固定顺序挑材料，而是**算出每个候选材料「满足该槽位性质需求」要付出的真实成本**（这次会损失多少价值），挑最划算的。 |
| **怎么用** | 默认开启，什么都不用做。想改成旧行为：设置里关掉「合成」→「智能选材：按性质性价比自动匹配」（`ocs.pick.smart`）。 |
| **源码位置** | `Core\CraftSelector.cs:94-149`（`SelectForRecipe`：主流程）、`CraftSelector.cs:54-72`（`Usable`：候选资格）、`CraftSelector.cs:157-197`（`Best`/`Score`：打分）、`CraftSelector.cs:216-244`（`Compare`：比较规则，第一段是 `:220-224` 的临时瓶判据）、`CraftSelector.cs:252-266`（`PreferTempBottle`：临时瓶判据实现）、`CraftSelector.cs:44` / `:47`（两个阈值常量）。 |

**四个组成部分**（对应任务里的「成本 / 稀缺材料保留 / 位置偏好 / 平局兜底」）：

1. **成本**：`QualityModel.CostPerQuality` = `本次损失价值 / 该槽位需要的性质量`（`Core\QualityModel.cs:221-234`）。整件消耗的槽位按**整件价值**算，按耐久消耗的槽位按**比例价值**算（`ModSettings.cs:107`）。
2. **稀缺材料保留**：先扫一遍所有槽位，找出「**只有一件候选**、而且用掉就没了」的物品（`CraftSelector.cs:109-117`，受 `ocs.pick.reserve_scarce` 控制），然后在别的槽位避开它。同时按「候选数升序」先满足最挑剔的槽位（`CraftSelector.cs:120-122`）。
3. **位置偏好**：只在成本相近时才起作用（`CraftSelector.cs:200-213` 的 `PlaceScore`）：优先地面 / 优先身上 / 不优先容器内 / 不优先已穿戴。
4. **平局兜底**：成本差距 ≤ 25% 视为「相近」，依次比位置 → 性质充足度 → 低价值 → 低耐久，**最后用 `GetInstanceID()` 兜底**，保证同样条件下每次都选同一件，可复现（`CraftSelector.cs:216-244`）。差距 > 25% 时直接选便宜的那个，不看偏好。

**与原版 / 旧模组的差别**（`CraftSelector.cs:21-40`）：旧模组把 7 个开关按固定顺序拼成比较器链，取 `List.Sort` 后的 `Last()`，有三个问题：① 顺序硬编码（「优先地面」永远压过「优先低价值」）；② 只比 `condition` 和 `GetValue`，比不出真实性价比；③ 平局依赖 `List.Sort` 的不稳定顺序。关掉 `ocs.pick.smart` 后会退回这套旧的顺序逻辑（`CraftSelector.cs:277-329` 的 `LegacyCompare`，同样带上面那条临时瓶规则），顺带修掉旧实现的三个 bug：`PreferOnBody`/`PreferOnFloor` 忘记乘方向符号、液体比较里 `break` 应为 `continue`、未注册液体用索引器会抛异常（`CraftSelector.cs:272-276`）。

**优先用临时瓶里的同类液体（10-17 06:37:06 版新增，玩家反馈原文「同类液体优先消耗临时瓶子中液体」）**：同一个液体槽位既能用临时瓶（`craftingbottle`）里的某种液体、也能用真瓶子里装的**同一种液体**时，自动分配**优先挑临时瓶那份** —— 临时瓶 300 秒后连瓶带液体一起消失（§2.7），里面的液体本来就"注定要倒掉"，拿它顶比倒真瓶子划算，所以这条判据排在成本带**之前**（`CraftSelector.PreferTempBottle`，`Core\CraftSelector.cs:252-266`；智能模式在 `Compare` 的 `:220-224` 调用，兼容模式 `LegacyCompare` 在 `:281-292` 也插了同一条 ⇒ 关不关 `ocs.pick.smart` 行为一致）。只对「同一层液体」生效（`x.Use.LiquidId == y.Use.LiquidId`），不同液体之间不比较；手动指定真瓶子仍然照办（见 §2.2）；这与「优先倒进已有同类液体的瓶子」是两件事（后者是存放侧设置 `compare_liquid_stacking_enabled`，见 §3 表）。

**硬规则（原版就有，本模组保留）**：`item.favourited == true` 的物品**永不参与消耗**（`CraftSelector.cs:54-72`，注释见 `CraftSelector.cs:58`：教学关就是靠这个保护小刀）。

### 2.2 自由选择材料（记住你的选择）

| | |
|---|---|
| **作用** | 你可以指定某个槽位用哪一件材料，模组会记住这个选择，之后合成一直用它。 |
| **怎么用** | 见 §2.6 的两个界面。每个槽位一行，**点材料名（末尾带 `▾`）就地展开候选表，点哪件就用哪件**；M 窗口里另有 `◀` / `▶` 可以盲翻；点「自动（推荐）」把这个槽位交还给算法。候选表里**液体槽位的候选也写成「液体名（容器名）」**（例 `净水（水壶）`），选的是"哪一件容器"，显示的是它会倒出的那层液体（`CraftText.MaterialLabel`，`Core\CraftText.cs:123`）。 |
| **源码位置** | `Core\CraftSession.cs:103-123`（`RememberPick`）、`CraftSession.cs:125-134`（`ClearPick`）、`CraftSession.cs:136-154`（`ResolvePick`）、`CraftSession.cs:156-190`（`ApplyOverrides`：把记忆的选择套到本次选材结果上，并做去重）、`UI\MaterialWindow.cs:780-823`（`DrawPickList`：候选表，点一项即 `RememberPick`）、`MaterialWindow.cs:465-483`（`CyclePick`：M 窗口 `◀`/`▶` 的实际逻辑）、`MaterialWindow.cs:761-778`（`TogglePick`/`ToggleDest`/`ClosePickers`：开哪张表、收另一张）。 |

细节：

- 记忆的键是「**配方下标 → 槽位下标 → 物品 InstanceID**」（`CraftSession.cs:27` 的 `PickMemory`），**只存在内存里、不写盘**，重启游戏就清空（`CraftSession.cs:20-27`）。
- 换材料时只认「候选池里仍然存在、且仍然可用」的物品：`ApplyOverrides` 会校验 `CraftSelector.Usable`，物品没了或不再可用就退回算法自己挑（`CraftSession.cs:156-190`）。
- **去重保护**：同一件「会被整件消耗掉」的物品**不能同时填两个槽位**；若你的手动选择造成冲突，第二个槽位会被换成别的候选，换不到就留空（`CraftSession.cs:156-190`，注释原文 `CraftSession.cs:153`）。液体槽与非整件消耗的槽位不参与这个去重（`CraftSession.cs:168-172`）。
- 界面上的「自动」按钮 = `CraftSession.ClearPick` + 刷新（`UI\MaterialWindow.cs:436-441`、`MaterialWindow.cs:515-521`）。

### 2.3 消耗量提示进 C 键界面

| | |
|---|---|
| **作用** | 按 C 打开原版合成界面、选中一个配方后，材料说明文字**后面会追加一段逐槽明细**：这个槽位要什么性质、会用哪一件材料、这次消耗多少、这件材料还能用几次、产物会存到哪。 |
| **怎么用** | 默认开启（`ocs.ui.consumption`）。不需要任何操作，打开 C 界面就能看到。 |
| **源码位置** | `Core\CraftText.cs:157-201`（`ConsumptionBlock`：文本的生成）、`Patches\PatchUI.cs:18-39`（`PlayerCamera.IngredientTextForRecipe` 的后缀，把文本追加到原版材料文字后）、`Core\QualityModel.cs:200-220`（`Describe`：mL / 耐久 -x% / 整件消耗 三种写法）。 |

文本实际长这样（颜色标签见 `CraftText.cs:157-201`，文案键见 `Core\Loc.cs:52-57`）：

```
需要
1. 帆布 · 布料 1   帆布  耐久 -12.5%   还能用 8 次
2. 任意液体 · 水 100   净水（水壶）  100 mL   还能用 3 次
将存放于  背包槽 4
```

- 逐槽显示**性质需求**（`CraftText.cs:57-76` 的 `SlotLabel` + `CraftText.cs:77-98` 的 `QualityLabel`），取名规则与原版 `PlayerCamera.IngredientTextForRecipe` 一致（`CraftText.cs:20-21`）。
- **液体槽位报的是"液体"本身**（20:51:19 版起）：显示成「液体名（容器名）」，例 `净水（水壶）`。名字 = 这一槽**实际会倒出来的那一层液体**（`QualityModel.LiquidOf`，`QualityModel.cs:161`，与 mL 数字同源），显示名走 `CraftText.LiquidName`（`CraftText.cs:99`：`localeFromItem` 时用 `Locale.GetItem`，否则用 `Locale.GetOther(localeName)`），拼装见 `CraftText.MaterialLabel`（`CraftText.cs:123`）。第三方模组塞进来的**未注册液体**（例 `Blood O+`）原样显示液体 id。固体槽位照旧显示物品名。
- **消耗量**三选一（`QualityModel.cs:200-220`）：液体 → `{0:0.#} mL`（`Loc.cs:65`）；按耐久消耗 → `耐久 -{0:0.#}%`（`Loc.cs:66`，数字 = `Amount × 100`）；整件消耗 → 「整件消耗」（`Loc.cs:54`）。
- **还能用几次**：`Loc.cs:55` 的「还能用 {0:0.#} 次」，固体按 `floor(当前耐久 / 单次消耗)`，液体按 `floor(瓶内可用量 / 单次用量)`（`QualityModel.cs:63-160`）。
- 缺料时该槽位显示红字「没有找到可用材料」（`CraftText.cs:157-201` 内用 `Loc.cs:33` 的 `ocs.win.empty`）。
- **「将存放于 …」**：这一行来自 `CraftText.cs:202-231` 的 `ResultDestination`（液体走 `CraftSession.PreviewLiquid`，固体走 `PlacementPlanner.PredictOne`），追加在整段末尾（`CraftText.cs:157-201` 末尾）。
- 打开「显示详细数值」（`ocs.ui.verbose`）后，每行还会补一个灰色的「位置」（`CraftText.cs:157-201` 中段、`CraftingScanner.cs:194-222` 的 `WhereOf`）。

**为什么这段文本里没有任何图标标签**（开发者注意）：原版 `PlayerCamera.RefreshCurrentlySelectedRecipe` 是**按 `<sprite>` 字符出现的顺序**摆放材料预览图标的，多插一个 sprite 就会让图标与槽位错位 —— 所以这里只追加纯文本（`Patches\PatchUI.cs:6-17`、`Core\CraftText.cs:7-12`；原版行为见 `_GameSource\Assembly-CSharp\PlayerCamera.cs:671`、`:714`）。

**临时瓶的完整逻辑（本模组与旧模组差别最大的一处）**：

1. 合成开始时若没有手动指定瓶子，预测会挑一个「**一次装得下**」的瓶子当作首选目标（`PlacementPlanner.cs:184-199`：`allowPartial: false`）。
2. 真正倒液时按四级顺序走（`PlacementPlanner.cs:205-248` 的 `Pour`）：
   ① 首选目标瓶 → ② 余量（> 0.5 mL）**依次续进其它合适的瓶子**（`allowPartial: true`，每倒一瓶都会记一笔「已存放」）→ ③ 还有余量且允许临时瓶 → **现场做临时瓶** → ④ 还有余量则倒进原版挑中的瓶子兜底。
3. `PlacementPlanner.CreateTempBottle`（`PlacementPlanner.cs:271-311`）：`Utils.Create("craftingbottle", 玩家位置, 0f)` → `AddLiquid` → 把 `condition` 同步成填充率 → `Object.Destroy(go, 300f)`（与原版一致，`:297`）→ `body.AutoPickUpItem(it)` 收进背包 → 记一笔「已存放」。**只有一滴都没装进去的空瓶**才被 `Object.Destroy(go, 30f)` 在 30 秒后清掉（`PlacementPlanner.cs:290-292`）。
4. **装着液体的临时瓶 5 分钟后连瓶带液体一起消失** —— 与原版一致（10-17 05:47:09 版起从旧模组的「永不销毁」改回；注释原文见 `PlacementPlanner.cs:265-269`，`Object.Destroy(go, 300f)` 在 `PlacementPlanner.cs:297`）。原版 `RecipeResult.SpawnResult` 在没有任何瓶子能装下时也会造一个 `craftingbottle`，紧接着同样 `Object.Destroy(gameObject, 300f)`（`_GameSource\Assembly-CSharp\RecipeResult.cs:59-64`；`RecipeResult.cs:45-52` 是那条「单种液体且一次装得下」的苛刻筛选）。旧模组的问题更严重：它先把临时瓶塞进背包，再挂 5 分钟定时器（`docs\流体存放逻辑重做方案.md:20`）。**唯一例外**：瓶子做出来了却一滴都没装进去（说明这次没用上它），30 秒后就清掉（`:290-292`）。所以合成完请尽快把液体倒进正式容器。
5. 装空了的临时瓶由游戏自己回收：`CustomItemBehaviour.cs:261-264` 对 `craftingbottle` 且 `CurrentTotal == 0f` 的物件直接 `Object.Destroy`（本模组没有改这段）。
6. 原版**禁止**把液体倒进 `craftingbottle`（`_GameSource\Assembly-CSharp\Body.cs:1570-1576` 只对目标做 `id != "craftingbottle"` 检查），所以「临时瓶 → 长期容器」的自动归并**没有实现**（方案 D 的 `liquids_temp_auto_migrate` 只是一份方案，见 §4）。
7. 想完全不要临时瓶：关掉 `ocs.liquid.tempbottle`（`ModSettings.cs:161-164`，文案说明关闭后液体产物会掉在地上）。

**收藏的容器不接液体（10-17 07:00:28 版新增，玩家反馈）**：给容器打上星标（游戏里对物品按收藏键，星标来自 `_GameSource\Assembly-CSharp\Item.cs:24` 的 `favourited`、名字前面的星标见 `Item.cs:62`）之后，**本模组不会把液体倒进它**：自动规划直接跳过（`PlacementPlanner.LiquidCandidates` `:327` 里的 `SkipFavorited`），候选表里它**整行置灰点不动**、并写明 `已收藏（本模组不往里倒液体）`（`ocs.store.bottle.favorited`，`Loc.cs:83`；置灰由 `BlockedReason` `:421` 驱动），连原版兜底那一步也会被拦下并留一条证据行 `[实测] 收藏保护：… 已收藏，为了不动它，… 没有存放。`（`PlacementPlanner.cs:244-256`）。开关是 `ocs.liquid.skip_favorited`（默认开，见 §3 第 25 项）；关掉即恢复「收藏的瓶子照样接液体」。这条规则和原版对**材料**的态度一致 —— 收藏的东西不会被消耗（`RecipeItem.cs:29`），本模组把它延伸到液体落点上。**注意**：如果所有瓶子都被收藏、`ocs.liquid.tempbottle` 又关着，这部分液体**会流失**，不过合成前的预测行会先说明去向（`PredictLiquid` 用的是同一套 `LiquidCandidates`）。

## 5. 测试清单

**通用准备**：启动游戏，`BepInEx\LogOutput.log` 里应能看到 `OptimisedCraftingSystem 1.0.0 已加载（Harmony 补丁已应用）。`（`Plugin.cs:45`）。以下每组给「前置条件 / 操作步骤 / 预期现象 / 出问题时看什么日志关键字」。日志前缀全部取自源码中的真实字符串。

### T1 普通合成与存放提示

- **前置**：背包里至少有一个空槽位；`notify_where_stored` 保持默认开。
- **步骤**：按 C → 选一个只需 1–2 种常见材料、产物是固体的配方 → 点「合成」。
- **预期**：合成成功，屏幕上方弹出「已存放：背包槽 N」或「已存放：<容器名>（剩余 x kg）」；产物确实出现在提示说的位置。
- **日志关键字**：出错时看 `[Session] 播报失败：`（`CraftSession.cs:346-349`）、`[Place] 存放失败：`（`PlacementPlanner.cs:129-177`）、`[Store] 按预测存放失败，退回原版：`（`Patches\PatchStorage.cs:14-63`）。

### T2 缺材料不能合成

- **前置**：找一个缺少至少一种材料的配方。
- **步骤**：在 C 界面选中它，观察材料文字与合成按钮，按下合成键。
- **预期**：追加的消耗明细里对应槽位显示红字「没有找到可用材料」，合成被拒绝（播放拒绝音、什么也不消耗）。
- **日志关键字**：`[Recipe] 智能选材失败，退回原版逻辑：`（`Patches\PatchCrafting.cs:16-53`）、`[Scanner] 收集身上物品失败：` / `[Scanner] 地面扫描失败：`（`Core\CraftingScanner.cs:44-95`）。
- **依据**：任一无槽位满足时返回 `null` 让原版拒绝（`Patches\PatchCrafting.cs:16-53`，注释在 `:34`）。

### T3 收藏物品不被消耗

- **前置**：把一件会被某配方当材料消耗的**整件消耗**物品标记为收藏（favourited）。
- **步骤**：选中该配方 → 看材料明细 → 尝试合成。
- **预期**：收藏物品不会出现在该槽位的候选里，也不会被消耗；若它是唯一候选，则该槽位显示缺料。
- **日志关键字**：无需特定关键字；若合成仍然消耗了它，看 `[Recipe] 智能选材失败，退回原版逻辑：`（说明补丁没生效，退回原版）。

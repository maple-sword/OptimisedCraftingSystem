## 中文版

### Description

**Optimised Crafting System** 让合成变得可预期。原版合成界面只列「需要什么」，其余全靠试错：会消耗哪一件、掉多少耐久、产物塞进哪个容器、装在袋子里的零件会不会跟着消失。本模组把这些全部在**按下合成之前**写清楚，并且允许你逐项手动指定；同时修掉了两个长期存在的不合理行为——被当材料消耗的瓶子里剩下的液体不再凭空消失，装有物品的容器也可以作为材料使用。

本模组衍生自 **BetterInventoryLogic**（作者 BalaurBohemianBroken），选材算法、存放逻辑、液体处理与界面全部重写；许可 CC BY-SA 4.0，中英双语。

### Installation instructions

1. 安装 **BepInEx 5（x64 / Mono）** 到游戏根目录（`Casualties Unknown Demo\`），先运行一次游戏确认 BepInEx 正常工作。
2. 把 `OptimisedCraftingSystem.dll` 放进 `Casualties Unknown Demo\BepInEx\plugins\`。
3. **移除冲突文件**：删掉 `plugins\CraftingLogic.dll`（原模组）；如果装过旧名字的本模组，把 `plugins\BetterCraftingLogic.dll` 改名成 `BetterCraftingLogic.dll.disabled` 或移出 `plugins\`。两个名字同时存在会各加载一份，补丁重复生效。
4. 启动游戏。日志里出现 `Loading [Optimised Crafting System 1.0.0]` 与 `[自检] … 设置项=36 项` 即为正常；若提示「检测到旧模组」，说明第 3 步没做完。
5. 设置就在游戏自己的设置界面里（「游戏」页 35 个开关 +「输入」页 1 个热键），无需编辑任何 `.cfg`。

### Main features

**原模组已有的功能（本版全部保留）**

- 在游戏设置界面里增加 19 个开关，分「选材 / 存放 / 液体」三组。
- 合成选材：用 7 个偏好开关（优先地面 / 优先身上 / 不用容器里的 / 不消耗穿戴装备 / 优先性质充足 / 优先低价值 / 优先低耐久）排出一条比较链，排序后取最后一项。
- 产物存放：按 6 个存放偏好（优先容器、标签匹配、减重、更满、容量更大、容器耐久更好）挑接收容器，合成后提示放在哪里。
- 液体：允许/禁止灌入空瓶、允许/禁止混装、优先不混装的瓶子、优先已有同类液体的瓶子、优先更轻的瓶子；装不下时现场做临时瓶（原版规则 300 秒后销毁）。
- 原模组没有自己的界面、也没有注册热键，所有改动都在逻辑层生效，只在合成完成后弹一行提示。
- 合成后弹一行 `Stored: …` 告诉玩家产物去向。

**本版新增或重写的功能**

- **合成前消耗量提示**：C 键界面每个材料槽写清 `120 mL` / `整件消耗` / `耐久 −12%（还能用 8 次）`；液体槽显示「实际会倒出的那层液体名（容器名）」。
- **成本化智能选材**：不再只比偏好，而是算这次合成真实毁掉的价值（价值 / 耐久 / 位置 / 稀缺度）；成本差距超过 25% 直接选便宜的，25% 以内才轮到偏好开关；并保护「别处唯一的材料」不被当耗材。
- **存放预测 + 手动改派**：合成前就写明 `将存放于 帆布背包（剩余 3.2 kg）` / `右手` / `将放在地上`；点一下即可改到别的容器或瓶子，装载后逐项复核，复核失败退回原版，不虚报成功。
- **液体三级落点**：一次装得下 → 余量续瓶（多瓶分摊）→ 现场做临时瓶。
- **液体候选表列出全部瓶子**：身上、容器里、地上的瓶子都在表内，写明内容物与余量；自动不会用的也列出来并注明原因（混装 / 空瓶 / 容量 / 收藏），整行置灰点不动。
- **同类液体优先用临时瓶里的**（那份注定 5 分钟后消失）。
- **液体容器不堆叠**：只有内容物完全相同的瓶子才并成 `×2`，装不同液体的分开列。
- **收藏的容器不接液体**：打了星标的瓶子不会被灌，自动规划、候选表、兜底三处都拦。
- **被消耗容器内容物救援**：装有物品的容器也能当材料，内容物先摘出来保住、新容器出现时逐件装入；装不下掉在脚边并提示。
- **被消耗瓶子液体救援**：整件消耗瓶子时先把剩余液体倒进现场做的临时瓶，并在选材阶段优先挑液体最少的瓶子。
- **材料总览窗口（M，可改键）**：同 id 合并一行，显示数量、位置、性质、耐久、价值、能用它的配方数，可拖动。
- **Shift 悬停容器**：内容物明细、内容物总重、剩余空间。
- **可拖动覆盖层**：屏幕右侧紧凑显示当前配方的消耗与去向，拖动移动、双击复位。
- **设置与本地化**：36 项中英双语（跟随界面语言），注入的语言键不覆盖汉化模组，**「恢复默认」真的会重置本模组设置**。
- **工程与兼容**：所有补丁挂在 `Priority.Low`，别人接管时让路，与 `QoL Unknown`、`Crafting Tweaks`、`CUCoreLib`、`prosthetics` 等实测共存；扫描结果按帧缓存，配方再多也不增加扫描次数；自带 `[自检]`，启动时打印 14 个被补丁方法的归属。

### Requirements

- **Casualties: Unknown Demo**（Unity 2022.3.62f3 / Mono）。
- **BepInEx 5（x64，Mono）**，已在 `BepInEx 5.4.21` 上验证。
- **不能**与原模组 `CraftingLogic.dll`（BetterInventoryLogic）同时安装；也不能同时存在本模组的旧文件名 `BetterCraftingLogic.dll`。
- 不需要其他前置模组；不依赖 `CUCoreLib` 等任何库。
- 从旧名字升级时注意：设置键前缀由 `bcl.*` 改为 `ocs.*`，升级后本模组设置会回到默认值一次（旧的无关键留在 `settings.json` 里，不影响使用）。

## English version

### Description

**Optimised Crafting System** makes crafting predictable. Vanilla only tells you what a recipe needs — everything else you find out by trial and error: which item gets burned, how much durability disappears, which container swallows the result, whether the parts in your bag survive. This mod spells all of that out **before you press craft** and lets you override every decision. It also fixes two long-standing annoyances: liquid in a bottle consumed as an ingredient is no longer lost, and containers with items inside can finally be used as ingredients.

A rewrite of **BetterInventoryLogic** (by BalaurBohemianBroken): the picking algorithm, storage planning, liquid routing and both windows are new. Licensed CC BY-SA 4.0, Chinese + English.

### Installation instructions

1. Install **BepInEx 5 (x64 / Mono)** into the game root (`Casualties Unknown Demo\`) and run the game once to confirm BepInEx works.
2. Drop `OptimisedCraftingSystem.dll` into `Casualties Unknown Demo\BepInEx\plugins\`.
3. **Remove conflicting copies**: delete `plugins\CraftingLogic.dll` (the original mod); if an old `plugins\BetterCraftingLogic.dll` is still present, rename it to `BetterCraftingLogic.dll.disabled` or move it out of `plugins\`. Two names means two plugins and every patch applied twice.
4. Start the game. The log should show `Loading [Optimised Crafting System 1.0.0]` and `[Self-check] … settings=36`; a "legacy mod detected" message means step 3 was skipped.
5. Settings live in the game's own settings menu (35 toggles on the *Game* page, 1 keybind on *Input*) — no `.cfg` to edit.

### Main features

**Kept from the original mod**

- 19 toggles added to the game's settings menu, grouped as picking / storage / liquids.
- Ingredient picking: a comparison chain built from 7 preference toggles (prefer floor / prefer body / avoid container items / avoid worn gear / prefer richer quality / prefer lower value / prefer more worn), sorted with the last entry winning.
- Result storage: 6 storage preferences (containers first, matching tags, weight reduction, fuller, larger capacity, better condition) choose the receiving container, followed by a post-craft alert.
- Liquids: allow filling empty bottles, allow mixing, prefer unmixed bottles, prefer bottles that already hold the same liquid, prefer lighter bottles; a makeshift bottle is created when nothing fits (destroyed after 300 s, vanilla behaviour).
- Crafting screen merges identical ingredients into one line (`canvas ×3`).
- A `Stored: …` line after crafting reports where the result went.

**New or rewritten in this mod**

- **Pre-craft consumption display**: every ingredient slot states `120 mL`, `whole item`, or `durability −12% (8 uses left)`; liquid slots name the exact liquid layer and its container.
- **Cost-aware picking**: instead of preference-only ranking it computes what the craft actually destroys (value / durability / location / scarcity). Gaps over 25% go to the cheaper option outright; only within 25% do preferences decide. Scarce items (the only source for another slot) are protected.
- **Storage prediction + manual override**: `will be stored in: canvas backpack (3.2 kg free)` / `right hand` / `on the ground` before you craft; click to re-route to another container or bottle. Loading is verified afterwards and falls back to vanilla on failure — no more false "stored" messages.
- **Three-tier liquid routing**: fits in one bottle → split across bottles by free space → makeshift bottle.
- **Every bottle in the candidate list**: carried, inside containers and on the floor, each with contents and free space. Bottles the planner won't use are listed too, greyed out with the reason (mixing / empty / capacity / favourited).
- **Same liquid prefers the makeshift bottle** — that portion is doomed to vanish in 5 minutes anyway.
- **Liquid containers are never stacked**: only bottles with identical contents merge into `×2`.
- **Favourited containers never receive liquid** (planner, candidate list and fallback all block it).
- **Contents rescue for consumed containers**: filled containers can be ingredients; contents are lifted out first and loaded into the new container item by item, with overflow dropped at your feet and an alert.
- **Liquid rescue for consumed bottles**: leftover liquid is poured into a makeshift bottle first, and picking prefers the bottle holding the least liquid.
- **Materials overview window (M, rebindable)**: items merged by id with count, location, qualities, condition, value and how many recipes can use them; draggable.
- **Shift-hover a container**: contents breakdown, total contents weight, free space.
- **Draggable overlay**: a compact read-out of the current recipe's costs and destination on the right of the crafting screen; drag to move, double-click to reset.
- **Settings & localisation**: 36 entries in Chinese and English following the UI language; injected keys never overwrite translation packs; *reset to default* now actually resets them.
- **Engineering & compatibility**: all patches at Harmony `Priority.Low`, yielding when another mod already handled the call; verified alongside `QoL Unknown`, `Crafting Tweaks`, `CUCoreLib`, `prosthetics`. Scans are cached per frame, so more recipes no longer means more scanning. A built-in `[Self-check]` prints which mod owns each of the 14 patched methods.

### Requirements

- **Casualties: Unknown Demo** (Unity 2022.3.62f3 / Mono).
- **BepInEx 5 (x64, Mono)** — verified on `BepInEx 5.4.21`.
- **Not compatible** with the original `CraftingLogic.dll` (BetterInventoryLogic), nor with this mod's old filename `BetterCraftingLogic.dll` sitting next to it.
- No other mods required; no dependency on `CUCoreLib` or similar libraries.
- Upgrading from the old name: settings keys moved from `bcl.*` to `ocs.*`, so this mod's settings reset to defaults once (stale keys stay harmlessly in `settings.json`).

# Optimised Crafting System（原 BetterCraftingLogic）

> 合成之前，先告诉你**这次会花掉什么、东西会放到哪**。

原版合成界面只列「需要什么」，其余全靠猜：用哪个瓶子、会消耗多少耐久、背包满了往哪放、袋子里那堆零件会不会跟着消失。**这个模组把这些全部补上，而且每一项都能手动改。**

本模组脱胎于 **BetterInventoryLogic**（作者 BalaurBohemianBroken，CC BY 4.0），但选材算法、存放逻辑、液体处理与界面全部重写：原模组是「合成后补救 + 偏好排序」，这一版是「**合成前算清 + 手动可改**」。

- BepInEx 5（Mono）插件，GUID `maple.optimisedcraftingsystem`，程序集 `OptimisedCraftingSystem.dll`
- 与原模组 `CraftingLogic.dll` **不能同时安装**（启动时会在日志里报错提醒）
- 设置共 **36 项**，在游戏自己的设置界面里（「游戏」页 35 个开关 +「输入」页 1 个热键），存进游戏自己的 `settings.json`
- 中英双语；许可 **CC BY-SA 4.0**（详见 [NOTICE.md](NOTICE.md) 与 [LICENSE](LICENSE)）

## 与原模组（BetterInventoryLogic）的区别

| 方面 | 原模组 | 本模组 |
|---|---|---|
| **选材** | 7 个偏好开关排成一条比较链，排序后**取列表末尾**；只看偏好、**不算成本**，平局时等于随机 | 先算**真实成本**（这件东西为本次合成要付出什么、是否稀缺、会不会影响别的配方）：成本差距 >25% 直接选便宜的，≤25% 才轮到偏好开关。另加**稀缺保护**：唯一能提供某性质的工具不会被当耗材烧掉 |
| **消耗量** | 没有，配方说明里只有勾/叉图标 | C 键面板多一块「**需要**」：每槽写清 `120 mL` / `整件消耗` / `耐久 -12%（还能用 8 次）`；液体槽报的是「**实际会倒出的那层液体名（容器名）**」 |
| **存放** | 只在合成**之后**弹一句英文 `Stored: …`；而且 `LoadItem` 静默失败时照样报成功 | 合成**之前**就写明 `将存放于 帆布背包（剩余 3.2 kg）` / `右手` / `将放在地上`；装载后逐项复核（容器父级、槽位是否真的被占），复核失败就退回原版，**不虚报** |
| **改派** | 无（作者自己在源码里留了 TODO） | 点材料名或「将存放于」展开候选表，点一项即生效；表里第一行永远是「自动（推荐）」；手选会被记住，不可用的选项会被忽略 |
| **液体落点** | 只找「一次就装得下」的瓶子，装不下就现场做临时瓶 | 三级策略：一次装得下 → **余量续瓶**（多瓶分摊）→ 实在没地方才做临时瓶。候选表**列出身上、容器里乃至地上的每一个瓶子**（连内容物与余量），自动不会用的也列出来并写明原因、整行置灰 |
| **界面** | 没有任何界面（5 个补丁全是逻辑补丁） | **M** 打开材料总览窗口（880×560、可拖动、热键可在设置里改）；C 键面板右侧一条**紧凑覆盖层**显示当前配方的消耗与去向，**可拖动、双击复位**，点材料名直接展开候选表 |
| **临时瓶** | `Destroy(go, 300f)`：装着液体的瓶子 5 分钟后连液体一起消失（与原版一致） | **同样与原版一致**：装着液体的临时瓶 5 分钟后连瓶带液体一起销毁；一滴都没装进去的空瓶 30 秒后清掉 |
| **被消耗的容器** | 装液体的瓶子被当材料消耗时，**瓶里的液体直接消失**；装着东西的容器**根本不能当材料** | 液体不丢（先倒进现场做的临时瓶），且选材时**优先挑液体最少的瓶子**；装有物品的容器**能当材料**，内容物先摘出来保住、新产物出现时装进去，装不下就掉在脚边并提示 |
| **收藏容器** | 原版与旧模组都不管：打了星标的瓶子照样被灌液体 | **收藏（星标）的容器不会被倒入液体**（自动规划跳过、候选表置灰、手动也绕不过） |
| **兼容** | 用 `Prefix` 返回 `false` **整体替换**原版 `RecipeResult.SpawnResult`，顶掉别人的补丁，与 CUCoreLib 谁先执行不确定 | 不碰 `SpawnResult`：改用「合成前后开会话」+ 只在生成后接管存放；所有补丁挂在优先级 `Low`，别人接管时主动让路 |
| **性能** | 每次刷新配方列表，**每个可见配方各扫一遍**全物品 + 圆形物理查询（作者自己留了 "STILL get a lag spike" 的 TODO） | 扫描结果**按帧缓存**，一次刷新只扫一遍；配方再多也不增加扫描次数 |
| **设置与本地化** | 23 个开关全塞在「游戏」页、38 条语言键全是英文；注入用 `Dictionary.Add`（重复调用会抛异常）；**点「恢复默认」不会重置模组设置** | 36 项中英双语（跟随界面语言）；语言键**已存在的一律不覆盖**（汉化模组优先）；「恢复默认」真的会重置本模组设置 |

旧模组遗留的 28 条缺陷也已全部修掉，典型几类：比较链方向写反（地面/身上偏好的符号漏乘）、液体比较用 `break` 导致只比第一层、未注册液体走索引器会抛异常、「优先更满的容器」实现成「优先最空」、每帧重复全图扫描、语言注入覆盖汉化模组、以及上面提到的「报存放成功但其实没装进去」。

## 全部功能

**合成前**

- C 键界面的「需要」块：逐槽消耗量与产物去向。
- 缺料行为与原版完全一致（不会擅自放宽合成条件）。
- 覆盖层里的信息与 C 键面板同源，屏幕右侧常驻，不遮挡原版面板。

**选材**

- 智能选材：按真实成本挑材料（价值 / 耐久 / 来源 / 稀缺）。
- 兼容模式的旧顺序链也保留（关掉 `ocs.pick.smart` 即回到原模组的偏好排序，且已修掉它的方向错误）。
- 手选材料：候选表 + 记忆选择 + 「自动」复位；同一件物品不能同时占两个槽。
- 稀缺保护：别处唯一的材料不会被当耗材。

**存放**

- 合成前预测产物去向（容器 / 槽位 / 装备位 / 地上）。
- 手动改派容器，装载后复核，失败自动退回原版。
- 合成后提示「已存放：帆布背包、右手」，跟随语言，顺序稳定。

**液体**

- 三级落点策略（一次装下 → 余量续瓶 → 临时瓶）。
- 候选表列出全部瓶子（含地上），不可用的置灰并写明原因（混装 / 空瓶 / 容量 / 收藏）。
- **同类液体优先用临时瓶里的**（那份注定 5 分钟后消失）。
- **液体容器不堆叠**：总览与 Shift 提示里只有内容物完全相同的瓶子才并成 `×2`。
- **收藏的容器不接液体**（自动 + 手选 + 兜底三处都拦）。
- 被消耗的瓶子里的液体先救进临时瓶，不跟着瓶子消失。

**被消耗的容器**

- 装有物品的容器可以当材料；内容物先摘出来、新容器出现时逐件装入。
- 装不下的掉在脚边并提示；新容器本身也装满时交回原版进背包。
- 两道安全网（合成开始与结束）保证不会有东西被永久冻住。

**界面**

- **M** 材料总览：同 id 合并成一行（数量 / 位置 / 性质 / 耐久 / 价值 / 能用它的配方数），点一行看详情并跳到配方。
- **Shift + 悬停容器**：内容物明细、内容物总重、剩余空间。
- 覆盖层与窗口都可以拖动。

**兼容与工程**

- 补丁全部 `Priority.Low`，与 `QoL Unknown`、`Crafting Tweaks`、`CUCoreLib`、`prosthetics` 等实测共存。
- 自带 `[自检]`：启动时打印 14 个被补丁方法的归属，以及设置项数、配方/物品种类数、字体。
- 14 个补丁类、36 项设置、中英双语。

## 设置

全部 36 项都在游戏自己的设置界面里（35 个开关在「游戏」页、热键在「输入」页），存在游戏的 `settings.json`，**不用** BepInEx 的 `.cfg`。完整表格（含每项的作用与默认值）见 [docs/新功能说明与设置.md](docs/新功能说明与设置.md)。

几项最常用的：

| 设置 | 默认 | 作用 |
|---|---|---|
| `ocs.pick.smart` | 开 | 按真实成本选材（关掉退回原模组的偏好排序） |
| `ocs.pick.reserve_scarce` | 开 | 稀缺保护 |
| `ocs.store.predict` | 开 | 合成前预测并显示产物落点 |
| `ocs.store.honor` | 开 | 真的按预测执行（关掉只显示不干预） |
| `ocs.liquid.tempbottle` | 开 | 装不下时现场做临时瓶（5 分钟后连液体一起消失，与原版一致） |
| `ocs.liquid.skip_favorited` | 开 | 收藏的容器不接液体 |
| `ocs.craft.prefer_empty_bottle` | 开 | 整件消耗时优先挑液体最少的瓶子 |
| `ocs.craft.rescue_liquid` | 开 | 被消耗瓶子里的液体先救进临时瓶 |
| `ocs.craft.container_contents` | 开 | 装有物品的容器可以当材料，内容物跟着搬 |
| `ocs.ui.consumption` / `ocs.ui.stacking` | 开 | C 键界面的消耗量提示 / 相同材料合并显示 |
| `ocs.tip.container_totals` / `ocs.tip.container_weight` | 开 | Shift 悬停显示内容物与总重 |
| `ocs.window.enabled` / `ocs.window.floor` | 开 | 材料总览窗口 / 是否包含 10 米内地面物品 |

## 安装

1. 把 `OptimisedCraftingSystem.dll` 放进 `Casualties Unknown Demo\BepInEx\plugins\`
2. 删掉 `plugins\CraftingLogic.dll`（原模组 BetterInventoryLogic）；如果装过旧名字的本模组，把 `BetterCraftingLogic.dll` 改名成 `BetterCraftingLogic.dll.disabled` 或移出 `plugins\`（**两个名字同时存在会各加载一份，补丁重复生效**）
3. 启动游戏，日志里应出现：

```
Loading [Optimised Crafting System 1.0.0]
OptimisedCraftingSystem 1.0.0 已加载（Harmony 补丁已应用）。
[Loc] 界面语言判定为 中文。
[自检] 语言=中文 设置项=36 项 热键=M 字体=Microsoft YaHei
[自检] 配方=278 个 物品类型=371 种 玩家=在场
[自检] Recipe.GetItemsForRecipe ← 本模组：maple.optimisedcraftingsystem/prefix(p200)；其它模组：com.HerobrinesProsthetics/prefix(p400)
```

（`[自检]` 会把 14 个目标方法逐条打印出来，是排查模组冲突最快的办法。若日志报「检测到旧模组」就说明第 2 步没做。）

## 兼容性

- 与 `QoL Unknown`、`Crafting Tweaks`、`CUCoreLib`、`prosthetics`、`Nutrition System`、`Hemopneumothorax`、`New Firearms` 及常见汉化包实测共存；本模组一律 `Priority.Low`，别人接管时让路。
- 只有两处刻意不让：一个 `High` 后缀（必须最后收尾）、一个通知型前缀（与 `QoL Unknown` 争「恢复默认」，两者都能正常工作）。

## 已知限制

- 手选的容器/材料不写盘，重启后回到「自动」；自动选材每次都会重新算。
- 液体槽位显示「这一槽会倒出来的那层液体（容器名）」；认不出的第三方液体（例 `Blood O+`）显示原始 id。
- 若所有能用的瓶子都被收藏、临时瓶又关着，这部分液体会流失（合成前的预测行会说明去向）。
- 被消耗容器的内容物装不进新容器时会掉在脚边，**不会自动帮你塞进背包**。
- 另一个模组若整体接管了这次合成（例 `prosthetics` 的钛合金手），本模组的「需要」块不代表实际消耗。
- IMGUI 面板依赖系统中文字体，一个都找不到时中文会显示成方框（`[自检]` 会打印实际拿到的字体名）。

## 从源码构建

```powershell
dotnet build src\OptimisedCraftingSystem.csproj -c Release -p:GameDir="D:\Steam\steamapps\common\Casualties Unknown Demo"
```

目标框架 `netstandard2.1`；游戏程序集从 `$(GameDir)\CasualtiesUnknown_Data\Managed` 引用（`<Private>false</Private>`，**不随仓库分发**）；产物在 `src\bin\Release\netstandard2.1\OptimisedCraftingSystem.dll`。
